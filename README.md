# fulcrum

[![ci](https://github.com/whoiam1101/fulcrum/actions/workflows/ci.yml/badge.svg)](https://github.com/whoiam1101/fulcrum/actions/workflows/ci.yml)
[![codeql](https://github.com/whoiam1101/fulcrum/actions/workflows/codeql.yml/badge.svg)](https://github.com/whoiam1101/fulcrum/actions/workflows/codeql.yml)
[![license](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
[![msrv](https://img.shields.io/badge/MSRV-1.60-orange.svg)](Cargo.toml)

Deterministic fixed-point math for Rust: bit-identical results on every platform, no floating point inside. Operators saturate and never panic; sums are exact and independent of order and thread count. `no_std`, no required dependencies, MSRV 1.60. Made for lockstep networking, replays and simulations that must agree across machines.

Types: `FixedFloat8` (Q4.4), `FixedFloat16` (Q8.8), `FixedFloat32` (Q16.16), `FixedFloat64` (Q32.32); vectors `Vec2<T>`, `Vec3<T>` over any of them.

> **Status:** stages 1–7 of the [roadmap](ROADMAP.md) are done: arithmetic, `mul_add`, `mul_div`, `lerp`, exact accumulators, correctly rounded `sqrt`, `rsqrt`, `hypot`; trigonometry within 1 ulp (`sin_turns`, `cos_turns` and, in radians, `sin`, `cos`, `sin_cos`, `tan`, `atan`, `atan2`, `asin`, `acos`) and the wrapping angle types `Angle8` … `Angle64`; the vectors `Vec2` and `Vec3` (`dot`, `cross`, lengths rounded once, correctly rounded `normalize`, `rotate`, `angle_to`); `log2`, `exp2`, `ln`, `exp` within ½ ulp plus a small margin, and `pow`, `powi` within 1 ulp; plain loops over slices of 8–32 bits that vectorize on SSE2, AVX2 and NEON, checked in CI; optional `serde`, `bytemuck` and `num-traits` support. The API may change before 1.0. Not on crates.io; use a git dependency pinned to a tag.

```toml
[dependencies]
fulcrum = { git = "https://github.com/whoiam1101/fulcrum", tag = "v0.7.1" }
```

## Example

```rust
use fulcrum::{ff64, FixedFloat64};

const SPEED: FixedFloat64 = ff64!(12.6);

let dt: FixedFloat64 = "0.016".parse().unwrap();
let step = SPEED * dt;
assert_eq!(format!("{:.4}", step), "0.2016");

assert_eq!(FixedFloat64::MAX + FixedFloat64::ONE, FixedFloat64::MAX);
assert_eq!(FixedFloat64::MAX.checked_add(FixedFloat64::ONE), None);

let xs = [ff64!(0.1), ff64!(0.2), ff64!(0.3)];
let mut left = FixedFloat64::accumulator();
left.extend(&xs[..1]);
let mut right = FixedFloat64::accumulator();
right.extend(&xs[1..]);
assert_eq!(left.merge(right).finish(), xs.iter().sum::<FixedFloat64>());
```

Local checks are recipes of the [`justfile`](justfile): `just` lists them, `just check` runs the fast ones, `just all` the gate before a push (lint, tests, oracle, MSRV, feature combinations, `cargo deny`). CI calls the same recipes where it can; the OS and target matrices, fuzzing, Kani and Lean stay in `.github/workflows`. Before contributing, install the hooks: `pre-commit install` (gitleaks, typos, actionlint, zizmor and the fast recipes on commit; tests, the MSRV build and `cargo deny` before push).

Verified by exhaustive tests of `FixedFloat8` and `FixedFloat16`, an exact rational oracle, fuzzing, Kani proofs and a golden hash on x86-64, ARM64 and 32-bit x86. CI runs on Linux, macOS and Windows and builds for `thumbv7em` without `std`.

## Benchmarks

Measured on 2026-11-21, commit `f980beb`, GitHub-hosted runner: AMD EPYC 9V74 80-Core Processor, x86_64 linux, rustc 1.100.0 (0ef1bc386 2026-11-09).

Generated by `bench/src/bin/report.rs` from [`bench/benches/ops.rs`](bench/benches/ops.rs). Operands in `[-2, 2)`, divisors in `±[0.5, 2)`. *Throughput*: 4096 independent operations, the compiler may vectorize. *Latency*: a dependent chain, each result feeds the next operation.

### Summary

- **Against `fixed`** (same formats, saturating operators): fulcrum is faster in 8 of 15 cases, on par in 4, slower in 3.
  - `+`: out of 3 cases, on par in 3.
  - `*`: out of 6 cases, faster in 6 (1.34–6.35×).
  - `/`: out of 6 cases, faster in 2 (1.10–1.49×), on par in 1, slower in 3 (1.07–1.28×).
- **Biggest win:** `*`, throughput of `FixedFloat16`, 6.35× faster than `fixed` I8F8.
- **Biggest loss:** `/`, throughput of `FixedFloat16`, 1.28× slower than `fixed` I8F8.
- **Combined operations** (`mul_add`, `mul_div`, `lerp`, dot product) against `fixed`: faster in 6 of 8 cases, on par in 0, slower in 2.
- **Loops over slices** (`+`, `-`, `*`, `mul_int`, `mul_add`, `lerp` on 8, 16 and 32 bits) against `fixed`: faster in 8 of 18 cases, on par in 8, slower in 2.
- **Square roots**, `FixedFloat32` vs `libm` `f32` (fulcrum correctly rounded, floats not once stored in the format, see the accuracy table): `sqrt` 3.47× slower; `rsqrt` 2.88× slower; `hypot` 3.01× slower.

- **Exponentials and logarithms**, `FixedFloat32`: against `libm` `f32` faster in 0 of 6, on par in 0, slower in 6; `exp` against `cordic` `I16F16` 1.16× faster (fulcrum within 1 ulp, see the accuracy table).

### How to read this

- A difference is reported only when the 95% confidence intervals of the two medians do not overlap and the medians differ by at least 5%; everything else is *on par*. Absolute numbers depend on the runner's CPU, ratios measured in the same run are what to compare.
- `fixed` is measured with `saturating_*`, the closest to fulcrum semantics. fulcrum additionally rounds `*` and `/` to nearest, while `fixed` truncates: fulcrum does more work per operation and returns a more accurate result.
- `i32`/`i64`/`i128` are plain integer arithmetic on the same loops, without rounding or saturation: a reference point for the cost of the integer operations themselves.
- `f32`/`f64` are the speed ceiling: hardware floats are fast, but their results may differ between platforms and compilers. The gap shows the price of bit-identical results.
- Reproduce locally: `cd bench && cargo bench --bench ops && cargo run --release --bin report`.

[![codeql](https://github.com/whoiam1101/fulcrum/actions/workflows/codeql.yml/badge.svg)](https://github.com/whoiam1101/fulcrum/actions/workflows/codeql.yml)
[![license](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)
[![msrv](https://img.shields.io/badge/MSRV-1.60-orange.svg)](Cargo.toml)

Deterministic fixed-point math for Rust: bit-identical results on every platform, no floating point inside. Operators saturate and never panic; sums are exact and independent of order and thread count. `no_std`, no required dependencies, MSRV 1.60. Made for lockstep networking, replays and simulations that must agree across machines.

Types: `FixedFloat8` (Q4.4), `FixedFloat16` (Q8.8), `FixedFloat32` (Q16.16), `FixedFloat64` (Q32.32); vectors `Vec2<T>`, `Vec3<T>` over any of them.

> **Status:** stages 1–4 of the [roadmap](ROADMAP.md) are done and stage 5 is written and tested, its Kani proofs and cross-platform checks pending: arithmetic, `mul_add`, `mul_div`, `lerp`, exact accumulators, correctly rounded `sqrt`, `rsqrt`, `hypot`; trigonometry within 1 ulp (`sin_turns`, `cos_turns` and, in radians, `sin`, `cos`, `sin_cos`, `tan`, `atan`, `atan2`, `asin`, `acos`) and the wrapping angle types `Angle8` … `Angle64`; the vectors `Vec2` and `Vec3` (`dot`, `cross`, lengths rounded once, correctly rounded `normalize`, `rotate`, `angle_to`); optional `serde`, `bytemuck` and `num-traits` support. The API may change before 1.0. Not on crates.io; use a git dependency pinned to a tag.

```toml
[dependencies]
fulcrum = { git = "https://github.com/whoiam1101/fulcrum", tag = "v0.5.0" }
```

## Example

```rust
use fulcrum::{ff64, FixedFloat64};

const SPEED: FixedFloat64 = ff64!(12.6);

let dt: FixedFloat64 = "0.016".parse().unwrap();
let step = SPEED * dt;
assert_eq!(format!("{:.4}", step), "0.2016");

assert_eq!(FixedFloat64::MAX + FixedFloat64::ONE, FixedFloat64::MAX);
assert_eq!(FixedFloat64::MAX.checked_add(FixedFloat64::ONE), None);

let xs = [ff64!(0.1), ff64!(0.2), ff64!(0.3)];
let mut left = FixedFloat64::accumulator();
left.extend(&xs[..1]);
let mut right = FixedFloat64::accumulator();
right.extend(&xs[1..]);
assert_eq!(left.merge(right).finish(), xs.iter().sum::<FixedFloat64>());
```

## Benchmarks

Measured on 2026-11-17, commit `dc65866`, GitHub-hosted runner: AMD EPYC 9V45 96-Core Processor, x86_64 linux, rustc 1.99.1 (58cf8f9c3 2026-10-13).

Generated by `bench/src/bin/report.rs` from [`bench/benches/ops.rs`](bench/benches/ops.rs). Operands in `[-2, 2)`, divisors in `±[0.5, 2)`. *Throughput*: 4096 independent operations, the compiler may vectorize. *Latency*: a dependent chain, each result feeds the next operation.

### Summary

- **Against `fixed`** (same formats, saturating operators): fulcrum is faster in 8 of 15 cases, on par in 4, slower in 3.
  - `+`: out of 3 cases, on par in 3.
  - `*`: out of 6 cases, faster in 6 (1.17–9.02×).
  - `/`: out of 6 cases, faster in 2 (1.22–1.35×), on par in 1, slower in 3 (1.17–1.32×).
- **Biggest win:** `*`, throughput of `FixedFloat16`, 9.02× faster than `fixed` I8F8.
- **Biggest loss:** `/`, throughput of `FixedFloat16`, 1.32× slower than `fixed` I8F8.
- **Combined operations** (`mul_add`, `mul_div`, `lerp`, dot product) against `fixed`: faster in 7 of 8 cases, on par in 0, slower in 1.
- **Square roots**, `FixedFloat32` vs `libm` `f32` (fulcrum correctly rounded, floats not once stored in the format, see the accuracy table): `sqrt` 3.42× slower; `rsqrt` 3.32× slower; `hypot` 4.23× slower.
- **Square roots**, `FixedFloat64` vs `libm` `f64` (fulcrum correctly rounded, floats not once stored in the format, see the accuracy table): `sqrt` 11.21× slower; `rsqrt` 3.52× slower; `hypot` 5.23× slower.
- **Trigonometry**, `FixedFloat32`: against `libm` `f32` faster in 0 of 9, on par in 0, slower in 9; against `cordic` `I16F16` faster in 5 of 7, on par in 1, slower in 1 (fulcrum within 1 ulp, see the accuracy table).
- **Trigonometry**, `FixedFloat64`: against `libm` `f64` faster in 2 of 9, on par in 0, slower in 7; against `cordic` `I32F32` faster in 7 of 7, on par in 0, slower in 0 (fulcrum within 1 ulp, see the accuracy table).
- **Cost of determinism**, `FixedFloat32` vs hardware `f32`: `+`, throughput 2.22× slower; `*`, throughput 8.94× slower; `*`, latency 1.69× slower; `/`, throughput 13.05× slower; `/`, latency 2.10× slower.
- **Cost of determinism**, `FixedFloat64` vs hardware `f64`: `+`, throughput 4.03× slower; `*`, throughput 9.43× slower; `*`, latency 2.64× slower; `/`, throughput 5.82× slower; `/`, latency 1.88× slower.

### Combined operations, ns per operation (throughput)

fulcrum rounds `mul_add`, `mul_div`, `lerp` and the dot product (`Accumulator::add_product`) once, to nearest. `fixed` uses `saturating_mul_add` and `saturating_lerp`, which truncate, `x * y / z`, which truncates twice, and a sum of saturating products, which truncates every term. Integers run the same loops with wrapping `x * y + z`, `x * y / z`, `x + (y - x) * t` and a sum of products.

### How to read this

- A difference is reported only when the 95% confidence intervals of the two medians do not overlap and the medians differ by at least 5%; everything else is *on par*. Absolute numbers depend on the runner's CPU, ratios measured in the same run are what to compare.
- `fixed` is measured with `saturating_*`, the closest to fulcrum semantics. fulcrum additionally rounds `*` and `/` to nearest, while `fixed` truncates: fulcrum does more work per operation and returns a more accurate result.
- `i32`/`i64`/`i128` are plain integer arithmetic on the same loops, without rounding or saturation: a reference point for the cost of the integer operations themselves.
- `f32`/`f64` are the speed ceiling: hardware floats are fast, but their results may differ between platforms and compilers. The gap shows the price of bit-identical results.
- Reproduce locally: `cd bench && cargo bench --bench ops && cargo run --release --bin report`.

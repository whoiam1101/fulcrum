# fulcrum 0.5: руководство по API

[English](API.md) · **Русский**

Как пользоваться библиотекой: какие есть типы, как создавать значения, что делают операции на границах, как сериализовать и как писать обобщённый код. Описывает `v0.5.0`.

## 1. Подключение

```toml
[dependencies]
fulcrum = { git = "https://github.com/whoiam1101/fulcrum", tag = "v0.5.0" }
```

Крейт `no_std`, без обязательных зависимостей, MSRV 1.60, без `unsafe` вне необязательной фичи `bytemuck`. Фичи (все выключены по умолчанию):

| Фича | Что даёт |
|---|---|
| `alloc` | ничего публичного в 0.1, задел |
| `std` | `std::error::Error` для `ParseError` и `OverflowError` (включает `alloc`) |
| `float-convert` | `to_f64`, `checked_from_f64`, `saturating_from_f64` — для отладки и рендера |
| `strict-overflow` | операторы паникуют вместо насыщения — только для тестов и CI движка |
| `serde` | `Serialize`, `Deserialize`: десятичная строка в текстовых форматах, сырое целое в двоичных (§14) |
| `bytemuck` | `Pod`, `Zeroable` — приведение срезов к байтам; единственный `unsafe` крейта (две реализации трейтов) |
| `num-traits` | `Zero`, `One`, `Bounded`, `Num`, `Signed` |

Всё публичное лежит в корне: `use fulcrum::{ff32, FixedFloat32, FixedFloat};`.

## 2. Типы

| Тип | Формат | Сырое | Диапазон | Шаг (ulp) | Литерал | Аккумулятор |
|---|---|---|---|---|---|---|
| `FixedFloat8` | Q4.4 | `i8` | `[-8, 7.9375]` | `2⁻⁴ = 0.0625` | `ff8!` | `Accumulator8` |
| `FixedFloat16` | Q8.8 | `i16` | `[-128, 127.996]` | `2⁻⁸ ≈ 0.0039` | `ff16!` | `Accumulator16` |
| `FixedFloat32` | Q16.16 | `i32` | `[-32768, 32767.99998]` | `2⁻¹⁶ ≈ 1.5·10⁻⁵` | `ff32!` | `Accumulator32` |
| `FixedFloat64` | Q32.32 | `i64` | `±2.1·10⁹` | `2⁻³² ≈ 2.3·10⁻¹⁰` | `ff64!` | `Accumulator64` |

Значение — это `raw / 2^FRAC_BITS`. Типы `Copy`, `Default` (= 0), `Eq`, `Ord`, `Hash`, `#[repr(transparent)]` над сырым целым. Порядок и равенство совпадают с порядком сырых целых: `NaN`, `-0` и бесконечностей нет.

Ассоциированные константы каждого типа: `FRAC_BITS`, `INT_BITS` (вместе со знаковым битом), `ZERO`, `ONE`, `NEG_ONE`, `HALF`, `MIN`, `MAX`, `DELTA` (один ulp).

Как выбрать ширину: `FixedFloat64` — по умолчанию для симуляции (координаты, скорости, время); `FixedFloat32` — когда важны память и скорость, а диапазона ±32768 с шагом 1.5·10⁻⁵ хватает; 8 и 16 бит — для компактных данных (сетевые пакеты, параметры, таблицы) и для тестов, потому что их можно перебрать целиком.

## 3. Как получить значение

```rust
use fulcrum::{ff32, ff64, FixedFloat32, FixedFloat64};
use core::convert::TryFrom;

const SPEED: FixedFloat64 = ff64!(12.6);
const NEG: FixedFloat32 = ff32!(-0.25);
const BIG: FixedFloat64 = ff64!(1_000_000);

let dt: FixedFloat64 = "0.016".parse().unwrap();
let n = FixedFloat32::from(7i16);
let m = FixedFloat32::try_from(-5i32).unwrap();
let third = FixedFloat32::saturating_from_ratio(1, 3);
let raw = FixedFloat32::from_bits(0x0001_8000);
let parts = FixedFloat32::from_parts(-2, 49152);
```

| Способ | Округление | Вне диапазона |
|---|---|---|
| `ff32!(…)` и другие литералы | к ближайшему, середина вверх | ошибка компиляции |
| `parse(s)` / `s.parse()` (`FromStr`), `const fn` | к ближайшему, середина вверх | `Err(ParseError)`, `kind() == Overflow` |
| `From<iN/uN>` | точно | не бывает: реализовано только там, где влезает всегда |
| `TryFrom<iN/uN>` (те из `i8…i128`, `u8…u128`, для которых нет `From`) | точно | `Err(OverflowError)` |
| `saturating_from_int(i128)`, `checked_from_int(i128)` | точно | насыщение / `None` |
| `saturating_from_ratio(num, den)`, `checked_from_ratio` (по сырому типу) | к ближайшему, середина вверх | насыщение / `None`; `den = 0` — как деление на ноль |
| `from_bits(raw)` | — | всегда точно |
| `from_parts(int, frac)`, `checked_from_parts` | — | насыщение / `None` |
| `checked_from_scaled_bits(raw, src_frac)`, `saturating_from_scaled_bits`, `wrapping_from_scaled_bits`: `raw / 2^src_frac` для любого `i128` и любого `src_frac` | к ближайшему, середина вверх, один раз | `None` / насыщение по знаку `raw` / младшие биты |
| `saturating_from_f64(x)`, `checked_from_f64(x)` (фича `float-convert`) | к ближайшему, середина вверх | насыщение / `None`; `NaN` → `0` / `None` |

`From` от целых есть: для `FixedFloat16` — `i8`; для `FixedFloat32` — `i8`, `u8`, `i16`; для `FixedFloat64` — `i8`, `u8`, `i16`, `u16`, `i32`. Для `FixedFloat8` — нет: даже `i8` в него не влезает.

`from_parts` и `int_part`/`frac_part` — пара обратных функций. Целая часть округлена к `-∞`, дробная — неотрицательная, в единицах ulp: `-1.25` в `FixedFloat32` это `(-2, 49152)`, потому что `-2 + 49152/65536 = -1.25`.

**Литералы** разбираются точно в compile time, без `f64`. `ff64!(0.1)` даёт ближайшее к десятичному `0.1` значение, а не к `0.1f64`. Разрешены `_` между цифрами и знак `-` перед литералом. Литерал всегда константа, его можно использовать в `const` и `static`.

**Строки**: грамматика `[+-]? цифры? ('.' цифры?)?`, хотя бы одна цифра. Экспоненты (`1e3`) и `_` нет, пробелы не обрезаются. `".5"`, `"5."`, `"+3"` допустимы. Разбор точный при любой длине строки: результат — правильно округлённое значение десятичного числа.

## 4. Арифметика

### Операторы

`+ - * / %`, унарный `-`, их `*Assign`-формы и варианты со ссылками (`&a + b`, `a + &b`, `&a + &b`) **насыщаются** и никогда не паникуют (без `strict-overflow`).

- `+`, `-`, `%` — точные.
- `*` и `/` округляют к ближайшему, **середина к `+∞`**. Правило одно для всей библиотеки: литералы, `parse`, сужение, `>>`, `div_int`, аккумуляторы. Пример на одном ulp `FixedFloat8`: `DELTA * HALF == DELTA` (0.03125 → 0.0625), а `-DELTA * HALF == 0` (-0.03125 → 0).
- `%` — остаток `self - rhs · trunc(self / rhs)`, со знаком делимого, как у целых.

### Деление на ноль

| Операция | Результат |
|---|---|
| `x / 0`, `saturating_div`, `wrapping_div`, `div_int(0)`, `saturating_from_ratio(n, 0)` | `MAX` при `x > 0`, `MIN` при `x < 0`, `0` при `x = 0` |
| `x % 0`, `saturating_rem`, `wrapping_rem` | `0` |
| `checked_div`, `checked_rem`, `checked_div_int`, `checked_recip`, `checked_from_ratio` | `None` |
| `overflowing_div`, `overflowing_rem` | результат как выше и `true` |
| `recip()` нуля | `MAX` |

### Явная семантика переполнения

Как у примитивных целых. Всё ниже — `const fn`.

| Операция | `checked_` → `Option` | `saturating_` | `wrapping_` | `overflowing_` → `(v, bool)` | оператор |
|---|---|---|---|---|---|
| сложение | `checked_add` | `saturating_add` | `wrapping_add` | `overflowing_add` | `+` |
| вычитание | `checked_sub` | `saturating_sub` | `wrapping_sub` | `overflowing_sub` | `-` |
| умножение | `checked_mul` | `saturating_mul` | `wrapping_mul` | `overflowing_mul` | `*` |
| деление | `checked_div` | `saturating_div` | `wrapping_div` | `overflowing_div` | `/` |
| остаток | `checked_rem` | `saturating_rem` | `wrapping_rem` | `overflowing_rem` | `%` |
| отрицание | `checked_neg` | `saturating_neg` | `wrapping_neg` | `overflowing_neg` | унарный `-` |
| модуль | `checked_abs` | `saturating_abs` (= `abs`) | `wrapping_abs` | `overflowing_abs` | — |
| `· 2ⁿ` | `checked_shl` | `saturating_shl` | `wrapping_shl` | — | `<< n` |
| `· n` (целое) | `checked_mul_int` | `mul_int` | `wrapping_mul_int` | — | — |
| `/ n` (целое) | `checked_div_int` | `div_int` | — | — | — |

`wrapping_*` берут результат по модулю `2^BITS` сырого значения: `MAX.wrapping_add(DELTA) == MIN`. Умножение и деление сначала округляют, потом заворачивают.

### Сдвиги

`x << n` — точное `x · 2ⁿ` с насыщением, любое `n` допустимо. `x >> n` — `x / 2ⁿ` с тем же округлением, что у `/`, поэтому `x >> 1 == x / 2` для любого `x`. Это **не** арифметический сдвиг сырого значения: `DELTA >> 1 == DELTA`, `-DELTA >> 1 == 0`. Нужен сдвиг битов — работайте с `to_bits()`.

`wrapping_shl(n)` при `n ≥ BITS` даёт `0`; в отличие от примитивов, `n` не маскируется.

### Прочее

| Метод | Что делает |
|---|---|
| `abs()` | модуль с насыщением: `MIN.abs() == MAX` |
| `signum()` | `-1`, `0` или `1` |
| `is_negative()`, `is_positive()`, `is_zero()` | знак |
| `min`, `max` | как у `Ord`, но `const fn` |
| `clamp(lo, hi)` | не паникует; при `lo > hi` возвращает `hi` |
| `abs_diff(other)` | `|a - b|` с насыщением |
| `midpoint(other)` | `(a + b) / 2` без промежуточного переполнения, с общим правилом округления |
| `recip()` | `1 / x` с насыщением |
| `sqr()` | `x · x` с насыщением |
| `mul_int(n)`, `div_int(n)` | умножение (точное) и деление (с округлением) на целое сырого типа |

### Одно округление: `mul_add`, `mul_div`, `lerp`

Вычисляют точный результат от трёх операндов и один раз округляют и насыщают его. Промежуточное произведение не округляется и не насыщается, поэтому результат точнее той же цепочки операторов и не портится, когда за диапазон выходит только промежуточное значение.

| Метод | Значение | Вне диапазона | `checked_*` |
|---|---|---|---|
| `x.mul_add(a, b)` | `x · a + b` | насыщение | `checked_mul_add` |
| `x.mul_div(a, b)` | `x · a / b`; `b = 0` даёт `MAX`, `MIN` или `0` по знаку `x · a` | насыщение | `checked_mul_div`, `None` и при `b = 0` |
| `a.lerp(b, t)` | `a + (b - a) · t`: `t = 0` даёт ровно `a`, `t = 1` — ровно `b`, остальные `t` экстраполируют | насыщение | `checked_lerp` |

```rust
use fulcrum::{ff64, FixedFloat64};

let big = FixedFloat64::MAX;
assert_eq!(big * big / big, FixedFloat64::ONE);
assert_eq!(big.mul_div(big, big), big);
assert_eq!(ff64!(10).lerp(ff64!(20), ff64!(0.25)), ff64!(12.5));
```

С `strict-overflow` явные методы сохраняют семантику: насыщают, как `abs` и `mul_int`.

### Квадратные корни: `sqrt`, `rsqrt`, `hypot`

Все три правильно округлены к ближайшему (ошибка ≤ ½ ulp): результат — ближайшее к точному корню представимое значение. Середин не бывает: корень никогда не лежит ровно посередине между двумя значениями.

| Метод | Значение | Вне области или диапазона | `checked_*` |
|---|---|---|---|
| `x.sqrt()` | `√x`; не переполняется | `x < 0` даёт `0` | `checked_sqrt`: `None` при `x < 0` |
| `x.rsqrt()` | `1 / √x`; при `x > 0` не переполняется | `x ≤ 0` даёт `MAX`, как `recip(0)` | `checked_rsqrt`: `None` при `x ≤ 0` |
| `x.hypot(y)` | `√(x² + y²)`, квадраты точны и не переполняются | насыщение | `checked_hypot` |

```rust
use fulcrum::{ff32, FixedFloat32};

assert_eq!(ff32!(2).sqrt(), FixedFloat32::SQRT_2);
assert_eq!(ff32!(4).rsqrt(), ff32!(0.5));
assert_eq!(ff32!(3).hypot(ff32!(-4)), ff32!(5));
assert_eq!(FixedFloat32::MAX.hypot(FixedFloat32::MAX), FixedFloat32::MAX);
```

`rsqrt` — одно округление `1 / √x`, точнее, чем `x.sqrt().recip()` с двумя округлениями.

### Синус и косинус в оборотах: `sin_turns`, `cos_turns`

Угол в оборотах: `1.0` — это 360°, `0.25` — 90°. Важна только дробь оборота, поэтому приведение диапазона — маска битов: точное на любом входе, без переполнения, и игровой угол в оборотах ничего не теряет на `π`. Результат лежит в `[-1, 1]` и отличается от точного меньше чем на 1 ulp; у `FixedFloat8`, `FixedFloat16` и `FixedFloat32` перебором проверено, что каждый результат правильно округлён.

| Метод | Значение | Симметрии, бит в бит (`-x` при `x > MIN`: `-MIN` насыщается) |
|---|---|---|
| `x.sin_turns()` | `sin(2π·x)` | `sin_turns(-x) = -sin_turns(x)`, `sin_turns(x + 1) = sin_turns(x)` |
| `x.cos_turns()` | `cos(2π·x)` | `cos_turns(x) = sin_turns(x + ¼)`, `cos_turns(-x) = cos_turns(x)` |

```rust
use fulcrum::{ff32, ff64, FixedFloat32};

assert_eq!(ff32!(0.25).sin_turns(), FixedFloat32::ONE);
assert_eq!(ff32!(0.5).cos_turns(), -FixedFloat32::ONE);
assert_eq!(ff32!(1000.125).sin_turns(), ff32!(0.125).sin_turns());
assert_eq!(ff64!(0.125).sin_turns(), ff64!(0.125).cos_turns());
```

### Синус, косинус и тангенс в радианах: `sin`, `cos`, `sin_cos`, `tan`

Угол в радианах. Приведение диапазона точно умножает значение на 192 бита `2/π`, поэтому оно аккуратно на любом входе, включая `FixedFloat64::MAX`. `sin` и `cos` лежат в `[-1, 1]` и отличаются от точного значения меньше чем на 1 ulp; `tan` — меньше чем на 1 ulp от точного значения, ограниченного диапазоном. У `FixedFloat8`, `FixedFloat16` и `FixedFloat32` перебором проверено, что каждый результат правильно округлён.

| Метод | Значение | Симметрии, бит в бит (`-x` при `x > MIN`) |
|---|---|---|
| `x.sin()` | `sin x` | `sin(-x) = -sin(x)` |
| `x.cos()` | `cos x` | `cos(-x) = cos(x)` |
| `x.sin_cos()` | `(x.sin(), x.cos())`, одно приведение | |
| `x.tan()` | `tan x`, насыщается у полюсов | `tan(-x) = -tan(x)`, где нет насыщения (`MIN` и `-MAX` различаются) |
| `x.checked_tan()` | `tan x`, `None`, если округлённое значение вне диапазона | |

```rust
use fulcrum::{ff32, ff64, FixedFloat32, FixedFloat64};

assert_eq!(FixedFloat32::ZERO.sin_cos(), (FixedFloat32::ZERO, FixedFloat32::ONE));
assert_eq!(FixedFloat32::PI.cos(), -FixedFloat32::ONE);
assert_eq!(ff32!(-0.5).sin(), -ff32!(0.5).sin());
assert_eq!(FixedFloat64::FRAC_PI_2.tan(), FixedFloat64::MAX);
assert_eq!(FixedFloat64::FRAC_PI_2.checked_tan(), None);
assert_eq!(ff64!(1000000000).sin(), ff64!(0.545843449421226978302001953125));
```

`sin_cos` есть и в трейте `FixedFloat`. Угол, который только поворачивается и складывается, как в игре, точнее хранить в оборотах (`sin_turns`): там приведение — маска, и `π` в него не входит. Для углов, которые всё время поворачиваются, — типы углов ниже.

### Обратные функции: `atan`, `atan2`, `asin`, `acos`

Результат в радианах и отличается от точного значения меньше чем на 1 ulp; у `FixedFloat8`, `FixedFloat16` и `FixedFloat32` перебором проверено, что каждый результат (и каждая пара `atan2` у `FixedFloat8`) правильно округлён. Переполнений нет: модуль результата не больше `π`, а он помещается в любой тип, и `atan2` берёт точное отношение аргументов, какого бы размера они ни были.

| Метод | Значение | Диапазон | Симметрии, бит в бит |
|---|---|---|---|
| `x.atan()` | `atan x` | `[-π/2, π/2]` | `atan(-x) = -atan(x)` при `x > MIN` |
| `y.atan2(x)` | угол точки `(x, y)`, как `f64::atan2` | `(-π, π]`, после округления `[-π, π]` | `atan2(-y, x) = -atan2(y, x)` при `y ≠ 0` |
| `x.asin()` | `asin x`; `x` вне `[-1, 1]` прижимается к нему | `[-π/2, π/2]` | `asin(-x) = -asin(x)` |
| `x.acos()` | `acos x`; `x` вне `[-1, 1]` прижимается к нему | `[0, π]` | |
| `x.checked_asin()`, `x.checked_acos()` | `None` вне `[-1, 1]` | | |

`atan2(0, 0) = 0` и `atan2(0, x) = π` при `x < 0`: `-0` нет, поэтому разрез по отрицательной полуоси уходит в `+π`.

```rust
use fulcrum::{ff32, ff64, FixedFloat32, FixedFloat64};

assert_eq!(ff32!(1).atan(), FixedFloat32::FRAC_PI_4);
assert_eq!(ff32!(0).atan2(ff32!(-1)), FixedFloat32::PI);
assert_eq!(ff32!(-1).atan2(ff32!(0)), -FixedFloat32::FRAC_PI_2);
assert_eq!(ff64!(0.5).asin(), FixedFloat64::FRAC_PI_6);
assert_eq!(ff32!(-1).acos(), FixedFloat32::PI);
assert_eq!(ff32!(2).asin(), FixedFloat32::FRAC_PI_2);
assert_eq!(ff32!(2).checked_asin(), None);
```

`atan2` есть и в трейте `FixedFloat`.

### Двоичные логарифм и экспонента: `log2`, `exp2`

В пределах 1 ulp от точного значения; у `FixedFloat8`, `FixedFloat16` и `FixedFloat32` перебором проверено, что каждый результат правильно округлён, а обе функции на этих типах монотонны.

| Метод | Значение | Вне области или диапазона |
|---|---|---|
| `x.log2()` | `log₂ x`, точно на степенях двойки; не переполняется | `x ≤ 0` даёт `MIN`, насыщение `-∞` |
| `x.checked_log2()` | то же | `None` при `x ≤ 0` |
| `x.exp2()` | `2^x`, точно на целых `≥ -FRAC_BITS`; `0` ниже `-FRAC_BITS - 1` | насыщается в `MAX` |
| `x.checked_exp2()` | то же | `None`, когда округлённый результат вне диапазона |

Разбиение `x` на целую и дробную части точное, поэтому `exp2` ничего не теряет ни на каком входе; `2^(-FRAC_BITS - 1)`, ровно половина ulp, округляется вверх до `DELTA` по правилу `*` и `/`.

```rust
use fulcrum::{ff32, FixedFloat32};

assert_eq!(ff32!(8).log2(), ff32!(3));
assert_eq!(ff32!(0.5).log2(), ff32!(-1));
assert_eq!(ff32!(0).log2(), FixedFloat32::MIN);
assert_eq!(ff32!(0.5).exp2(), FixedFloat32::SQRT_2);
assert_eq!(ff32!(-17).exp2(), FixedFloat32::DELTA);
assert_eq!(ff32!(15).exp2(), FixedFloat32::MAX);
assert_eq!(ff32!(15).checked_exp2(), None);
```

### Натуральные логарифм и экспонента: `ln`, `exp`

Те же гарантии, что у `log2` и `exp2`: в пределах 1 ulp от точного значения, у `FixedFloat8`, `FixedFloat16` и `FixedFloat32` перебором проверено, что каждый результат правильно округлён, а обе функции монотонны.

| Метод | Значение | Вне области или диапазона |
|---|---|---|
| `x.ln()` | `ln x`, точно в `1`; не переполняется | `x ≤ 0` даёт `MIN`, насыщение `-∞` |
| `x.checked_ln()` | то же | `None` при `x ≤ 0` |
| `x.exp()` | `e^x`, точно в `0`; `0` ниже примерно `-(FRAC_BITS + 1) · ln 2` | насыщается в `MAX` |
| `x.checked_exp()` | то же | `None`, когда округлённый результат вне диапазона |

`exp` приводит `x` точным кратным `ln 2 / 256` со 112 дробными битами, поэтому ошибка приведения много меньше ulp на любом входе, в том числе у верхней границы диапазона `FixedFloat64`.

```rust
use fulcrum::{ff32, FixedFloat32};

assert_eq!(ff32!(1).exp(), FixedFloat32::E);
assert_eq!(ff32!(0).exp(), ff32!(1));
assert_eq!(FixedFloat32::E.ln(), ff32!(1));
assert_eq!(ff32!(0).ln(), FixedFloat32::MIN);
assert_eq!(ff32!(-12).exp(), ff32!(0));
assert_eq!(ff32!(11).exp(), FixedFloat32::MAX);
assert_eq!(ff32!(11).checked_exp(), None);
```

### Степени: `pow`, `powi`

`x.pow(y)` — это `2^(y · log₂ x)` с логарифмом в 120 дробных битов, поэтому ошибка показателя много меньше ulp при любом `y` типа; `x.powi(n)` — то же для целого `n: i32`. Обе в пределах 1 ulp на всех ширинах (`½ + 2^-5.7` ulp у `FixedFloat64`, `½ + 2^-37` до `FixedFloat32`). У каждой пары `FixedFloat8` и `FixedFloat16` проверено, что результат правильно округлён, кроме случая, когда точная степень лежит ровно посередине между двумя значениями (как `(3/8)³` у `FixedFloat16`): такая середина может округлиться в любую сторону, не обязательно к `+∞`. У `FixedFloat64` результат в пределах `2^-5.7` ulp от середины (такие бывают около `MAX`) тоже может округлиться не в ту сторону. Точно представимый результат получается точно.

| Метод | Значение | Вне области или диапазона |
|---|---|---|
| `x.pow(y)` | `x^y`; `x^0 = 1` для любого `x`; `0^y = 0` при `y > 0`; отрицательное `x` берёт знак нечётного целого `y` | `0^y` при `y < 0` даёт `MAX`; отрицательное `x` с нецелым `y` даёт `0`; насыщается в `MAX` или `MIN` по знаку |
| `x.checked_pow(y)` | то же | `None` в каждом из этих случаев |
| `x.powi(n)` | `x^n`, `n: i32` | как у `pow` |
| `x.checked_powi(n)` | то же | `None`, когда округлённый результат вне диапазона или `x = 0`, `n < 0` |

```rust
use fulcrum::{ff32, FixedFloat32};

assert_eq!(ff32!(4).pow(ff32!(0.5)), ff32!(2));
assert_eq!(ff32!(2).pow(ff32!(0.5)), FixedFloat32::SQRT_2);
assert_eq!(ff32!(-2).powi(3), ff32!(-8));
assert_eq!(ff32!(-2).pow(ff32!(0.5)), ff32!(0));
assert_eq!(ff32!(-2).checked_pow(ff32!(0.5)), None);
assert_eq!(ff32!(0).powi(-1), FixedFloat32::MAX);
assert_eq!(ff32!(10).checked_powi(5), None);
```

`log2`, `exp2`, `ln`, `exp`, `pow` и `powi` есть и в трейте `FixedFloat`.

### Углы: `Angle8` … `Angle64`

Угол хранится всеми битами беззнакового целого как доля оборота `raw / 2^BITS`: у `Angle8` 256 шагов на оборот, у `Angle16` 65 536, у `Angle32` и `Angle64` шаг `1.46·10⁻⁹` и `3.4·10⁻¹⁹` радиана. `+`, `-` и унарный `-` заворачиваются по модулю оборота, поэтому угол, который всё время поворачивается, не нуждается в приведении, никогда не насыщается, а сумма поворотов не зависит от порядка. Каждый `AngleN` идёт в паре с `FixedFloatN`: синус и косинус — `FixedFloatN`, в пределах 1 ulp (у `Angle8`, `Angle16` и `Angle32` перебором проверено, что каждый результат правильно округлён и равен `sin_turns` того же угла).

| Метод | Значение |
|---|---|
| `ZERO`, `DELTA`, `QUARTER_TURN`, `HALF_TURN`, `BITS` | константы |
| `from_bits(u)`, `to_bits()` | сырая доля оборота |
| `from_turns(x)` | `x` оборотов, точно: важна только дробь `x` |
| `to_turns()` | угол в оборотах, в `[0, 1)`, к ближайшему |
| `from_radians(x)` | `x / 2π` по модулю оборота, к ближайшему; точное приведение через 192 бита `2/π`; `from_radians(-x) = -from_radians(x)` |
| `to_radians()` | угол в радианах, к ближайшему: точное значение в `[-π, π)`, округлённое — в `[-PI, PI]` (чуть ниже `HALF_TURN` оно округляется вверх до `PI`); `HALF_TURN` даёт `-PI` |
| `sin()`, `cos()`, `sin_cos()` | в пределах 1 ulp; `sin` нечётный, `cos` чётный, `cos(a) = sin(a + QUARTER_TURN)` бит в бит |
| `a + b`, `a - b`, `-a`, `+=`, `-=`, `wrapping_*` | по модулю оборота |
| `a.scale(x)`, `a * x`, `a *= x` | `a · x` по модулю оборота, к ближайшему (середина к `+∞`), `a` берётся в `[-½, ½)` оборота: скорость поворота × шаг времени |

```rust
use fulcrum::{ff32, Angle16, Angle32, FixedFloat32};

let mut heading = Angle32::from_radians(FixedFloat32::FRAC_PI_2);
let rate = Angle32::from_turns(ff32!(0.25));
heading += rate * ff32!(0.5);
heading += Angle32::HALF_TURN + Angle32::HALF_TURN;
let (s, c) = heading.sin_cos();
assert_eq!(Angle16::QUARTER_TURN.sin_cos().0, fulcrum::FixedFloat16::ONE);
assert_eq!(Angle32::HALF_TURN.to_radians(), -FixedFloat32::PI);
assert_eq!(Angle32::from_turns(ff32!(1.25)), Angle32::QUARTER_TURN);
assert!(s > c);
```

`Ord` нет: у углов на круге нет порядка. Трейт `FixedAngle` (все методы и константы выше, сырой тип `Bits` и парный тип `Fixed`) и ассоциированный тип `FixedFloat::Angle` позволяют обобщённому коду перейти от типа с фиксированной точкой к его типу угла.

### Векторы: `Vec2`, `Vec3`

`Vec2<T>` и `Vec3<T>` над любым типом с фиксированной точкой, с открытыми полями `x`, `y` (`z`), `#[repr(C)]`: две или три компоненты подряд, без выравнивающих байтов. Алиасы для каждой ширины: `Vec2f8` … `Vec2f64`, `Vec3f8` … `Vec3f64`. Правила те же, что у скаляров: операторы насыщаются покомпонентно (и паникуют под `strict-overflow`), а каждый метод, сводящий компоненты вместе, округляет один раз из точных промежуточных.

| Метод | Значение |
|---|---|
| `new`, `splat(v)`, `ZERO`, `X`, `Y`, `Z` | конструкторы и единичные векторы |
| `a + b`, `a - b`, `-a`, `a * b`, `a * s`, `s * a`, `a / s`, `*Assign` | покомпонентно, как операторы компоненты; `a * b` — покомпонентное произведение |
| `min`, `max`, `abs`, `lerp(b, t)` | покомпонентно; `lerp` округляет один раз на компоненту |
| `dot`, `length_sq`, `distance_sq`, `perp_dot` (`Vec2`), `cross` (`Vec3`) | точная сумма точных произведений, одно округление и насыщение; разность компонент вне диапазона даёт `MAX` у расстояний |
| `length`, `distance` | правильно округлённый корень точной суммы квадратов (`hypot` у `Vec2`) |
| `try_normalize`, `normalize` | каждая компонента, `x`, делённое на длину, правильно округлена; нулевой вектор даёт `None` и `ZERO` |
| `clamp_length_max(max)`, `clamp_length(min, max)` | приведение к границе, когда вектор длиннее (короче) её: точное сравнение, правильно округлённые компоненты; `min` проверяется первым, как в `glam`; отрицательные границы считаются `0` |
| `perp()` (`Vec2`) | `(-y, x)`, четверть оборота против часовой |
| `rotate(angle)` (`Vec2`) | поворот на угол типа `T::Angle` с синусом и косинусом на 62 битах: в пределах 1 ulp при длине меньше `2^(57 - FRAC_BITS)` (любой вектор до `FixedFloat32`, `3.3·10⁷` у `FixedFloat64`); четверти оборота точны |
| `angle_to(b)` | `Vec2`: знаковый угол от `a` к `b` в `(-π, π]`; `Vec3`: угол между ними в `[0, π]`; `atan2` точных векторного и скалярного произведений, в пределах 1 ulp; `0` для нулевого вектора |
| `to_le_bytes`, `from_le_bytes`, `to_be_bytes`, `from_be_bytes` | компоненты по порядку, каждая в своём формате (§8) |

```rust
use fulcrum::{ff32, Angle32, FixedFloat32, Vec2, Vec2f32, Vec3};

let v = Vec2::new(ff32!(3), ff32!(4));
assert_eq!(v.length(), ff32!(5));
assert_eq!(v.normalize(), Vec2::new(ff32!(0.6), ff32!(0.8)));
assert_eq!(v.clamp_length_max(ff32!(2.5)), Vec2::new(ff32!(1.5), ff32!(2)));
assert_eq!(Vec2f32::X.rotate(Angle32::QUARTER_TURN), Vec2f32::Y);
assert_eq!(Vec2f32::X.angle_to(Vec2f32::Y), FixedFloat32::FRAC_PI_2);
let mut pos = Vec3::new(ff32!(1), ff32!(2), ff32!(3));
pos += Vec3::splat(ff32!(0.5)) * ff32!(2);
assert_eq!(pos, Vec3::new(ff32!(2), ff32!(3), ff32!(4)));
```

С `serde` вектор — кортеж компонент (`["1.5","-2"]` в JSON); с `bytemuck` `Vec2<T>` и `Vec3<T>` — `Pod`, когда `T` — `Pod`.

## 5. Округление и целые

| Метод | Правило | Переполнение |
|---|---|---|
| `floor` | к `-∞` | никогда |
| `ceil`, `checked_ceil` | к `+∞` | насыщение / `None` у `MAX` |
| `trunc` | к нулю | никогда |
| `fract` | `x - trunc(x)`, со знаком `x` | никогда |
| `round`, `checked_round` | к ближайшему, середина **от нуля** | насыщение / `None` |
| `round_ties_even`, `checked_round_ties_even` | к ближайшему, середина к чётному | насыщение / `None` |

Те же правила с результатом в виде целого сырого типа: `to_int_floor`, `to_int_ceil`, `to_int_trunc`, `to_int_round`, `to_int_round_ties_even`. Они не переполняются никогда, потому что целое сырого типа шире целой части.

Пример: `-1.25` → `floor = -2`, `ceil = -1`, `trunc = -1`, `fract = -0.25`. `2.5.round() = 3`, `(-2.5).round() = -3`, `2.5.round_ties_even() = 2`.

Обратите внимание: `round` (середина от нуля, как `f64::round`) отличается от правила `*` и `/` (середина к `+∞`).

## 6. Преобразования между ширинами

| Направление | Способ | Результат |
|---|---|---|
| узкий → широкий | `From` / `.into()` | всегда точно |
| широкий → узкий | `TryFrom` | дробная часть округляется к ближайшему (середина вверх); `Err(OverflowError)`, если целая часть не влезает |
| любой → любой | `T::saturating_from(x)` | округление, насыщение |
| любой → любой | `T::wrapping_from(x)` | округление, младшие биты |

```rust
let w: FixedFloat64 = ff16!(1.5).into();
assert_eq!(FixedFloat8::try_from(ff32!(1.03125)), Ok(ff8!(1.0625)));
assert!(FixedFloat8::try_from(ff32!(100)).is_err());
assert_eq!(FixedFloat8::saturating_from(ff32!(100)), FixedFloat8::MAX);
assert_eq!(FixedFloat8::wrapping_from(ff32!(100)), ff8!(4));
```

`saturating_from` и `wrapping_from` принимают любой `T: FixedFloat`, в том числе тот же тип.

## 7. Текст

**`Display`** печатает значение точно: у двоичной дроби с `F` битами не больше `F` десятичных знаков. Поэтому `ff32!(0.1)` печатается как `0.100006103515625`: это и есть хранимое значение.

С точностью `{:.N}` округляет к ближайшему, **середина к чётному**, как форматирование `f64`: `{:.1}` для `0.25` даёт `0.2`, для `0.75` — `0.8`. Поддержаны ширина, заполнитель, выравнивание, `+` и `0`: `format!("{:+08.3}", ff32!(3.14159)) == "+003.142"`.

`parse(display(x)) == x` для любого значения (для `FixedFloat32` проверено на всех 2³² значениях).

**`Debug`** печатает значение и сырые биты в hex: `1.5 (0x00018000)`. В логах сразу видно, что именно лежит в памяти.

**Ошибки разбора** — `ParseError` с методом `kind()`:

| `ParseErrorKind` | Когда |
|---|---|
| `Empty` | пустая строка или только знак |
| `InvalidDigit` | лишний символ: экспонента, пробел, `_`, вторая точка |
| `Overflow` | число не влезает в тип |

`ParseErrorKind` помечен `#[non_exhaustive]`, поэтому в `match` нужна ветка `_`.

## 8. Байты

`to_le_bytes`, `from_le_bytes`, `to_be_bytes`, `from_be_bytes` — сырое значение, `[u8; 1|2|4|8]`. Формат не зависит от платформы. Little-endian — канонический формат для снапшотов, реплеев и контрольных сумм:

```rust
assert_eq!(ff32!(1.5).to_le_bytes(), [0x00, 0x80, 0x01, 0x00]);
assert_eq!(FixedFloat32::from_le_bytes([0x00, 0x80, 0x01, 0x00]), ff32!(1.5));
```

Хеш состояния симуляции — это хеш байтов его чисел. `Hash` тоже детерминирован, но порядок и алгоритм зависят от хешера, поэтому для сравнения между машинами берите байты.

## 9. Константы

Правильно округлены для каждого типа, генерируются `tools/gen-tables` точной арифметикой:

`PI`, `TAU`, `FRAC_PI_2`, `FRAC_PI_3`, `FRAC_PI_4`, `FRAC_PI_6`, `FRAC_PI_8`, `FRAC_1_PI`, `FRAC_2_PI`, `SQRT_2`, `FRAC_1_SQRT_2`, `SQRT_3`, `FRAC_1_SQRT_3`, `E`, `LN_2`, `LN_10`, `LOG2_E`, `LOG2_10`, `LOG10_2`, `LOG10_E`, `GOLDEN_RATIO`, `DEG_TO_RAD`, `RAD_TO_DEG`.

У `FixedFloat8` нет `DEG_TO_RAD` (округляется до нуля) и `RAD_TO_DEG` (вне диапазона). Учтите грубость узких типов: `FixedFloat8::PI == 3.125`.

## 10. Суммы и аккумуляторы

Главное средство детерминизма при параллельных вычислениях.

**`Iterator::sum`** точная: все слагаемые складываются в `i128` без насыщения, насыщение происходит один раз в конце. Результат не зависит ни от порядка, ни от промежуточных переполнений. `fold` с `+` насыщается на каждом шаге, поэтому ведёт себя иначе:

```rust
let xs = [FixedFloat32::MAX, FixedFloat32::ONE, -FixedFloat32::ONE];
let s: FixedFloat32 = xs.iter().sum();
let f = xs.iter().fold(FixedFloat32::ZERO, |a, b| a + *b);
assert_eq!(s, FixedFloat32::MAX);
assert_eq!(f, FixedFloat32::MAX - FixedFloat32::ONE);
```

**`AccumulatorN`** — та же сумма в виде значения, которое можно делить между потоками:

| Метод | Что делает |
|---|---|
| `T::accumulator()`, `AccumulatorN::new()`, `ZERO`, `Default` | пустой |
| `add(x)`, `sub(x)`, `extend(iter)`, `collect()` | точное добавление |
| `add_product(a, b)` | точное неокруглённое произведение |
| `merge(other)`, `Sum<AccumulatorN>` | слияние частичных сумм; ассоциативно и коммутативно |
| `finish()` | один раз округляет и насыщает |
| `checked_finish()` | `None`, если итог вне диапазона |

```rust
let mut left = FixedFloat64::accumulator();
left.extend(&xs[..mid]);
let mut right = FixedFloat64::accumulator();
right.extend(&xs[mid..]);
assert_eq!(left.merge(right).finish(), xs.iter().sum::<FixedFloat64>());
```

Любое разбиение на потоки и любое дерево `merge` дают одни и те же биты. Аккумулятор — `Copy`, `Eq`, `Hash`: его состояние можно сравнивать и пересылать.

**Скалярное произведение** через `add_product` округляется один раз, а не на каждом слагаемом, поэтому точнее и тоже не зависит от порядка. Для `FixedFloat32`: `0.1·0.1 + 0.1·0.1` через `add_product` даёт `0.0200042724609375`, через `*` и `+` — `0.019989013671875`. У `Accumulator64` состояние 256-битное, поэтому его произведения в масштабе `2⁻⁶⁴` тоже точные.

**`Iterator::product`** — это просто `*` в порядке итерации. Округлённое умножение не ассоциативно, поэтому порядок задаёт вызывающий код.

Состояние — `i128` с заворачиванием: информация теряется только после более чем 2⁶³ слагаемых.

## 11. Обобщённый код: трейт `FixedFloat`

Запечатан: его реализуют только типы fulcrum. Он требует `Copy + Default + Ord + Hash + Debug + Display + FromStr<Err = ParseError>`, все арифметические операторы и их `*Assign`-формы.

Состав трейта:
- `type Bits`;
- константы `FRAC_BITS`, `INT_BITS`, `ZERO`, `ONE`, `NEG_ONE`, `HALF`, `MIN`, `MAX`, `DELTA`, `PI`, `TAU`, `FRAC_PI_2`, `E`, `SQRT_2`;
- методы `from_bits`, `to_bits`, `saturating_from_int`, `checked_from_int`, `checked_add/sub/mul/div`, `wrapping_add/sub/mul`, `abs`, `is_negative`, `floor`, `ceil`, `round`, `sqrt`, `hypot`, `lerp`, `sin_cos`, `atan2`, `log2`, `exp2`, `ln`, `exp`, `pow`, `powi` и ассоциированный тип `Angle` (тип угла той же ширины с трейтом `FixedAngle`: `from_turns`, `to_turns`, `from_radians`, `to_radians`, `sin`, `cos`, `sin_cos`, `scale`, `from_bits`, `to_bits`, константы, заворачивающиеся `+ - neg` и `* x`).

```rust
use fulcrum::FixedFloat;

fn total<T: FixedFloat>(xs: &[T]) -> T {
    xs.iter().fold(T::ZERO, |a, &b| a + b)
}
```

Всё остальное (`saturating_*`, `overflowing_*`, `to_int_*`, байты, аккумуляторы, остальные константы) есть только как собственные методы конкретных типов (`const` там, где сказано в §15). Трейт расширяется по мере этапов: на этапе 4 в него вошли `sin_cos` и `atan2`, на этапе 5 — `hypot` и `lerp` для обобщённых векторов.

## 12. `strict-overflow`

Для тестов и CI кода, который использует fulcrum. В выпускаемой сборке не включать.

С фичей паникуют вместо насыщения: операторы `+ - * / %` и их `*Assign`, унарный `-` от `MIN`, `<<`, `Iterator::sum` и `Iterator::product`. Деление и остаток на ноль в операторах тоже паникуют. Явные методы (`saturating_*`, `wrapping_*`, `checked_*`, `overflowing_*`, `AccumulatorN::finish`) ведут себя одинаково с фичей и без. Так в тестах движка ловится каждое неожиданное насыщение, а в релизе остаётся детерминированное поведение без паник.

Подключение только для тестов:

```toml
[dev-dependencies]
fulcrum = { git = "https://github.com/whoiam1101/fulcrum", tag = "v0.5.0", features = ["strict-overflow"] }
```

Учтите: Cargo объединяет фичи, поэтому в `cargo test` вашего крейта фича включится и для обычной зависимости.

## 13. `float-convert`

`to_f64()`, `checked_from_f64(x)`, `saturating_from_f64(x)`. Обе стороны работают с битовым представлением IEEE 754 через целые операции, поэтому сами по себе точны и детерминированы. `to_f64` точен, пока в сыром значении не больше 53 значащих битов (то есть всегда для 8–32 бит).

Назначение — отладка, тесты, вывод на экран, загрузка исходных данных. Как только значение прошло через `f64` арифметику, детерминизм потерян: в логику симуляции `f64` возвращать нельзя.

## 14. `serde`, `bytemuck`, `num-traits`

`serde`: текстовые форматы (JSON, YAML, TOML) получают точную десятичную строку `Display`, и `parse` возвращает те же биты: `ff64!(12.5)` — это `"12.5"`, `ff64!(0.1)` — `"0.1000000000931322574615478515625"`. Принимается и целое число (точно), а число с плавающей точкой вроде `12.6` без кавычек — только вместе с `float-convert`, с округлением как в `checked_from_f64`; без `float-convert` это ошибка, чтобы float не просочился в логику. Двоичные форматы (postcard, bincode, CBOR, MessagePack) получают сырое целое и кодируют его так же, как целое хранения (`i64` у `FixedFloat64`): у bincode это 8 байт, у postcard — varint.

`bytemuck`: `Pod` и `Zeroable`, поэтому `bytemuck::cast_slice` превращает `&[FixedFloat64]` в `&[i64]` или `&[u8]` и обратно без копирования (данные структурой массивов, буферы для рендера). Порядок байтов нативный, как у `to_bits().to_ne_bytes()`; для файлов и сети — `to_le_bytes` (§8).

`num-traits`: `Zero`, `One`, `Bounded`, `Num` и `Signed` с семантикой операторов: насыщение, округление к ближайшему. `Num::from_str_radix` принимает только основание 10; `Signed::abs_sub(a, b)` — это `max(a - b, 0)`.

## 15. Что гарантируется

- **Одинаковые биты везде.** Результат каждой операции зависит только от входных битов: не от платформы, компилятора, оптимизаций и числа потоков. Проверяется golden hash на x86-64, ARM64 и i686 в debug и release. Ошибка детерминизма считается уязвимостью ([SECURITY.md](SECURITY.md)).
- **Нет паник** без `strict-overflow`: ни на переполнении, ни на делении на ноль, ни на какой входной строке.
- **Точность.** `+ - %`, сравнения, сдвиг влево и расширение точны. `* / >>`, `div_int`, `mul_add`, `mul_div`, `lerp`, `sqrt`, `rsqrt`, `hypot`, сужение, разбор, литералы и аккумуляторы правильно округлены (ошибка ≤ ½ ulp, середина к `+∞`). Константы правильно округлены. `sin_turns`, `cos_turns`, `sin`, `cos`, `tan`, `atan`, `atan2`, `asin`, `acos`, `log2`, `exp2`, `ln`, `exp`, `pow` и `powi` — в пределах 1 ulp.
- **`const fn`** почти везде: все методы типов, кроме `saturating_from`, `wrapping_from` и `f64`-конверсий; у аккумуляторов `const` только `new`, `merge`, `finish`, `checked_finish`. Операторы — нет: трейты `core::ops` в стабильном Rust не `const`.
- **Стабильность.** До 1.0 API может меняться. Биты результатов существующих операций не меняются: ускорения обязаны давать те же биты.

## 16. Частые ошибки

- **Цепочки `*` не ассоциативны:** `(a * b) * c` может отличаться от `a * (b * c)` на ulp. Порядок операций — часть детерминированной логики, держите его фиксированным. Для сумм произведений используйте `add_product`.
- **`fold` с `+` вместо `sum`** насыщается на промежуточных значениях. Для детерминированной параллельной суммы — только `sum` или аккумуляторы.
- **`>>` округляет**, а не обрезает, как у целых.
- **`round` и `/` разрешают середину по-разному:** от нуля и к `+∞`.
- **Узкие типы грубые.** В `FixedFloat8` `PI == 3.125`, `1/3 ≈ 0.3125`. Шаг и диапазон смотрите в таблице §2.
- **`parse` не обрезает пробелы** и не понимает экспоненту: `"1e3"` и `" 1"` — `InvalidDigit`.
- **`f64` в логике** ломает детерминизм. `float-convert` нужен только на границе с внешним миром.
